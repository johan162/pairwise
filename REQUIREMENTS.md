
### **Formal Requirements for the Pairwise Comparison Ranking System (Active Bayesian Ranking)**

| **ID** | **Requirement**                                                                                                                                                                                                                                                                |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R1     | The system shall provide functionality to select a file which contains task description from a CSV file where each row contains one identifier and one requirement                                                                                                             |
| R2     | The overall aim of the system is to rank a number of tasks in two dimensions 1) Technical complexity , and 2) Business value. The result is then presented both as a graph with these two dimensions as X, and Y-axes and as task list with rank in both dimensions in a table |
| R3     | The system shall initialise a Bayesian skill/value estimate and uncertainty for each task at the start.                                                                                                                                                                        |
| R4     | The system shall calculate the total number of possible pairwise comparisons in each dimensions as ( \binom{n}{2} ), where ( n ) is the number of tasks.                                                                                                                       |
| R5     | The system shall select the next pair for comparison using an Active Bayesian Ranking method (Bradley–Terry model with uncertainty sampling), prioritising pairs that maximise information gain and coverage, rather than random selection.                                    |
| R6     | The system shall allow the user to select which task in the presented pair is more valuable.                                                                                                                                                                                   |
| R7     | The system shall update the Bayesian skill/value estimates and uncertainties for both tasks after each comparison, using the outcome.                                                                                                                                          |
| R8     | The system shall record each completed comparison in persistent storage to avoid duplication.                                                                                                                                                                                  |
| R9     | The system shall persist the current state (skill/value estimates, uncertainties, counts, completed comparisons, and comparison graph) in a JSON file after each vote.                                                                                                         |
| R10    | The system shall compute and display the percentage of progress as ( \frac{\text{completed comparisons}}{\text{total comparisons}} \times 100 ).                                                                                                                               |
| R11    | The system shall compute and display the Kendall Tau correlation coefficient between the current ranking and the Bayesian posterior sample ranking as a measure of certainty.                                                                                                  |
| R12    | The system shall display the current Kendall Tau value rounded to three decimal places.                                                                                                                                                                                        |
| R13    | The system shall estimate and display the number of comparisons required to achieve 60%, 70%, 80%, and 90% certainty, based on the Bayesian model’s convergence and coverage.                                                                                                  |
| R14    | The system shall provide an explanation of what it means for a ranking to be “X% correct” (agreement in X% of all possible pairwise comparisons, as measured by Kendall Tau).                                                                                                  |
| R15    | The system shall display the current ranking of tasks sorted by Bayesian skill/value estimate in descending order.                                                                                                                                                             |
| R16    | The system shall provide a web interface using Flask that displays: (a) two tasks for comparison, (b) progress percentage, (c) Kendall Tau value, (d) certainty estimates, (e) inconsistency warnings and level, and (f) current ranking list.                                 |
| R17    | The system shall allow the user to submit their choice via clickable buttons in the web interface.                                                                                                                                                                             |
| R18    | The system shall redirect the user back to the main page after each vote to present a new pair.                                                                                                                                                                                |
| R19    | The system shall prevent duplicate comparisons by checking both direct and reverse pair order before presenting a new pair.                                                                                                                                                    |
| R20    | The system shall run as a Flask application accessible at `http://127.0.0.1:5000` by default.                                                                                                                                                                                  |
| R21    | The system shall support resuming from the last saved state when restarted.                                                                                                                                                                                                    |
| R22    | The system shall use Kendall Tau as the primary metric for ranking quality assessment.                                                                                                                                                                                         |
| R23    | The system shall use the Bayesian model’s convergence and coverage for estimating certainty thresholds (e.g., 60%, 70%, etc.).                                                                                                                                                 |
| R24    | The system shall allow termination of the voting process at any time without data loss.                                                                                                                                                                                        |
| R25    | The system shall ensure that the user interface is modern with a professional dark theme with highlights                                                                                                                                                                       |
| R26    | The system shall detect and warn the user of inconsistencies (cycles) in the pairwise comparison graph after each vote.                                                                                                                                                        |
| R27    | The system shall display an assessment of the current inconsistency level as a percentage of problematic edges.                                                                                                                                                                |
| R28    | **Deployment:** The system shall be deployable as a containerised application using Podman.                                                                                                                                                                                    |
| R29    | **Deployment:** The container image shall include all dependencies (Flask, pandas, scipy, numpy) and expose port `5000` for HTTP access.                                                                                                                                       |
| R30    | **Deployment:** The container shall mount a volume for persistent storage of the state file and input CSV file.                                                                                                                                                                |
| R31    | **Deployment:** The container shall provide an environment variable for specifying the path to the tasks file.                                                                                                                                                                 |
| R32    | **Deployment:** The container shall run the Flask app as the default entry point.                                                                                                                                                                                              |
| R33    | The system shall use every possible technique to reduce the number of comparisons needed to still achive acceotable, but not perfect ranking                                                                                                                                   |
| R34    | The system is used by first having a session that ranks all tasks according to technical complexity, then a separate session for ranking business value                                                                                                                        |
| R35    | Each set of Tasks and ranks are considered to be one project                                                                                                                                                                                                                   |
| R36    | Each project result is persisted on disk in a SQLite DB                                                                                                                                                                                                                        |
| R37    | The system have functionality to load previous projects , modify and save them                                                                                                                                                                                                 |
| R38    | Each project has Meta-datas such as date for each sessions, name, purpose, and notes                                                                                                                                                                                           |
| R39    | The system should be written as a Python 3.13 program with small files with a clear purpose and solid model-view-controller style architecture                                                                                                                                 |
| R40 | The Python project should use "mkdocs" as documentaiton system and all documentation files stored under "docs/" directory. Use a professional dark theme for documentation |
| R41 | The Python project should be controlled and setup with a pyproject.toml file”
| R42 | All build dependencies should be setup with: pip install -e ".[dev]" 
| R43 | All documentation build dependencies should be setup with:  pip install -e ".[docs]"
