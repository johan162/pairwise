# Theory Behind the Ranking

## Why Pairwise?
Humans are notoriously bad at absolute estimation (e.g., "This task is a 7/10"). We are much better at relative comparison (e.g., "Task A is harder than Task B"). Pairwise comparison leverages this strength to build a robust ranking.

## Bayesian Ranking (TrueSkill / Bradley-Terry)
This system uses a probabilistic model inspired by **TrueSkill** and the **Bradley-Terry model**.

### The Model
Each item $i$ has a hidden "skill" or "value" parameter $\mu_i$ and an uncertainty $\sigma_i$.
- $\mu$ (Mu): The estimated mean value of the item.
- $\sigma$ (Sigma): The system's uncertainty about that value.

When Item A "beats" Item B in a comparison:
1.  The system increases $\mu_A$ and decreases $\mu_B$.
2.  The system decreases $\sigma_A$ and $\sigma_B$ (it becomes more confident).

### Gaussian Distribution
We model the skill of each item as a Gaussian distribution $N(\mu, \sigma^2)$. The probability that Item A beats Item B is calculated based on the overlap of their distributions.

## Active Learning (Uncertainty Sampling)
A naive pairwise approach requires comparing every item with every other item ($O(n^2)$), which is impractical for large lists.

This system uses **Active Learning** to select the "most informative" pair to compare next.
It looks for pairs that:
1.  **Have high uncertainty** (large $\sigma$).
2.  **Are close in rank** (similar $\mu$).

By focusing on these pairs, the system converges to a stable ranking much faster, often requiring only $O(n \log n)$ comparisons.

## Kendall Tau Coefficient
To measure how "stable" or "certain" the ranking is, we use the **Kendall Tau rank correlation coefficient**.
- We compare the current ranking (based on $\mu$) with a ranking generated by sampling from the posterior distributions.
- A value close to **1.0** indicates high certainty (the ranking is unlikely to change significantly with more votes).

## Calculating the Scores
The "Score" displayed in the results table corresponds directly to the mean parameter $\mu$ of the item's Gaussian distribution.

### 1. Initialization
*   Every task starts with a default score ($\mu$) of **25.0**.
*   Every task starts with a high uncertainty ($\sigma$) of **8.333**.
*   This implies that initially, the system assumes 99% of tasks fall between 0 and 50 (since $25 \pm 3\sigma \approx 0 \dots 50$).

### 2. The Update Step
When you vote that **Task A > Task B**, the system calculates a performance difference and updates the scores using Bayesian inference (specifically, Gaussian density filtering):

*   **Task A's score increases**: $\mu_A \leftarrow \mu_A + \Delta$
*   **Task B's score decreases**: $\mu_B \leftarrow \mu_B - \Delta$
*   **Uncertainty decreases**: Both $\sigma_A$ and $\sigma_B$ are reduced, as the system has gained information.

The magnitude of the change ($\Delta$) depends on the "surprise" of the result:
*   **Expected Outcome**: If a high-ranked item beats a low-ranked item, the scores change very little.
*   **Upset**: If a low-ranked item beats a high-ranked item, the scores change significantly to correct the ranking.

### 3. Complexity vs. Value
The system maintains **two separate ranking engines**: one for "Technical Complexity" and one for "Business Value". These are mathematically identical but operate on completely independent data. A task can have a high Value score (e.g., 35.0) and a low Complexity score (e.g., 15.0).

### 4. Interpretation
*   **Relative, not Absolute**: The scores are relative units. A score of 30.0 doesn't mean "30 hours" or "$30k". It simply means it is ranked higher than a task with 25.0.
*   **Probability of Superiority**: The difference in scores represents the probability that one item is better than another. A difference of roughly **4-5 points** implies a ~75% probability that the higher-scored item is truly superior.
